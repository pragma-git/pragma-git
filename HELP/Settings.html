Overview

The settings are displayed in the following four tabs :

  • Software , where software and git settings are handled
  • Repository , where repositories are handled
  • Branch , where branches of repository selected in "Repository tab" are handled
  • System info , which display information relevant to support, and the system path as seen by Pragma-git

Repository tab

(click on tab)

The repository settings have two parts :

  • Repository table , where you may select one of the repositories you have defined
  • Tools , a set of tabs with tools acting on repositories

The "Repository table"

The rows show the settings for the repositories you have defined so far.

The first column "Project folder" shows the path to your active repositories, either on your local PC or on an SSH server (marked with a [ssh] badge). Hovering over the folder name expands it to display the full path. The radio-button selects the active repository. In the "Branch" tab the branches in the selected repository are listed.

Inaccessible repositories and failure reasons: When a repository cannot be accessed or verified, its "Project folder" path is dimmed and prefixed with a warning indicator ! along with the specific reason:

  • (key rejected) — The SSH server refused connection because your SSH public key is not registered in the server's ~/.ssh/authorized_keys, or the wrong key was used.
  • (not a folder) — The specified directory does not exist on your computer or the remote server.
  • (not a repo) — The directory exists but is not an initialized Git repository (missing .git).
  • (no network) — The server hostname or IP address cannot be reached over the network.
Note: The same failure reasons and warning indicators are also displayed directly in the main window repository dropdown menu.

Fixing broken SSH connections: When an SSH repository fails authentication (such as (key rejected)), a button appears next to the failure reason. Clicking opens the SSH Connection Configuration dialog, where you can select an existing SSH key, generate a new ED25519 key pair, deploy your public key to the server, and click to immediately re-verify and restore access to the repository.

The second column "Group" allows you to categorize repositories into named groups (e.g. by project, client, or team).

  • Assigning or editing a group: Hovering over or clicking a repository's group cell reveals a text input field and a dropdown selector. You can type a new group name (press Enter to confirm or Esc to cancel) or pick an existing group from the dropdown list. To remove a repository from a group, select None (Remove from group) from the dropdown or clear the input text.
  • Filtering by group: The column header features a filter dropdown (Group (All) by default). Selecting a group filters the table view to show only repositories belonging to that group, or choose Ungrouped to view repositories with no group assigned. When a filter is applied, the header text is highlighted with a distinct background block (blockTextHighlight) harmonized with your color theme to clearly indicate that a filter is active.
  • Sticky filter: The selected group filter is automatically saved in settings.json and remembered across application sessions.
  • Automatic fallback: If the active group filter results in zero shown repositories (for example, if all repositories in that group are removed or reassigned to another group), Pragma-git automatically falls back to the Group (All) filter so you are never left with an empty list.
  • Main menu integration: Defined groups also organize the main window repository dropdown menu into dedicated submenus for each group, alongside Recent, Ungrouped, and All.

The third column "Web" displays the Git provider icon (such as GitHub, GitLab, Bitbucket, Gitea, etc.) for repositories with a remote URL. Clicking the icon opens the repository directly in your default web browser.

The fourth column "Remote repository" shows the address of a connected remote repository ("origin"). If this is not defined, you are working with a purely local repository. If defined, the connection status is shown with red color if login fails, or with green color if login works.

The fifth column has the button. The function of this button is to store an edited remote address and update the connection status.

The sixth column has the button, which removes the selected repository from Pragma-git's list. The files remain completely intact both locally and on the server/remote, and the repository can be re-added at any time by dropping the folder onto the main window or via the tab.

About forked repositories


If you try to clone a 'forked' repository, Pragma-git tries to get the url for the original (parent) repository automatically, and write the parent url as 'upstream' remote.

Forking is the process of starting with somebody elses repository, and making it your own. In Github and similar providers forking is performed from the web interface. The fork process then creates a copy in your own repository (called origin), and also remember where it came from (upstream). The beauty of keeping the relation to the parent, is that you can update the changes from the parent to your own repository, as the parent evolves. The parent is called "upstream" and is a remote repository. Your own remote repository is called "origin".

Sometimes, you want to transfer code you have developed in your forked repository back to "upstream". This is done through something called a "pull request" or "merge request". Typically this is done on your remote repository's (github, gitlab, ...) web page.

You still have the opportunity to update your repository with new additions from the "upstream" repository. This is done using the main window merge button ( ). The upstream changes are found under the button and the submenu "remotes". Changes that have not been merged, are indicated by an " ! " mark.

More about working with multiple remote repositories can be found below (multiple remotes section )

Working with multiple remotes

Apart from the fields described above, to set the remote repository for "origin" (the remote repository you typically push and pull from), you may have additional remote repositories. Typically, if you "fork" a remote repository, you will have two remotes: "origin" which is the one you work with, and "upstream" which is the original repository (which probably is continuously being worked on by others). The point of keeping track of this original "upstream", is that things happen that you wish to include in your own repository.

When you have more than one remote, you can use the arrow buttons (◀ and ▶)to switch between the remotes. In this example I have forked the "imlook4d" repository (which is a research tool for medical images), and I have pressed the ▶ button once to see the original "upstream" path.

If you want, you can use the to add more remote repositories. As is, you can pull from these using the button as described above (fork section), but in the future also pushing to additional remote repositories may be implemented.

Note, that if you merge from a remote upstream repository (with the exception of "origin") you are allowed to pick any remote branch to merge into the current local branch. This may be useful, but is also a possible source for doing some unintentional. For "origin" the "push" and "pull" operations work directly with the corresponding local and remote branch, and the technicalities are hidden from the user.

Some words about remote repositories

It is already described, above, how you link your project to a remote repository; and also how you clone a remote repository to your local computer. This section describes how to set up user-names and passwords for remote repositories.

(I) Creating an account

There are multiple remote repository hosting services that you can use on internet. One popular site is Github (by Microsoft), which gives free accounts.

Get an account, go to the web interface, and create a new repository. You will get a link on the format https://github.com/JanAxelssonTest/test.git
which you need to copy.

(II) Authentication

Login to a repository may require some kind of authentication. Some alternatives are :

  1. Access token (Github has moved towards this -- see link
  2. Old fashioned user-name and password (this is being phased out by many git services, but may be applicable if you run your own git repository)

(III) Using your link (address / url)

Paste the link to your repository into the text-field under "Remote repository".

Alternative 1) access tokens, modify the link by adding the ACCESSTOKEN, and an @-sign :
https://ACCESSTOKEN@github.com/USERNAME/REPOSITORY_NAME.git. For instance :
https://25badab677c62a7a3e44e5dd123a916adab8580677e0ffbd@github.com/JanAxelssonTest/test.git

Alternative 2) username and passwords, modify the link by adding user:password, and an @-sign :
https://USER:PASSWORD@github.com/USERNAME/REPOSITORY_NAME.git For instance :
https://JanAxelssonTest:PASSWORD@github.com/JanAxelssonTest/test.git

The repository is set (and tested) by pressing the button. If the text becomes green, the remote repository is correctly defined. Adjust your remote repository text until the "Set" button creates a green text, then it should work.

If git is using a credential manager, you can now remove the :PASSWORD (note the :) and test if it now works without storing the password in the link. Also, if git forgets the password after a while, you will need to keep the password field or install a credential manager. Mac and Windows should be fine by default.

Branch tab

(click on tab)

The branches for a selected repository (in the repository table) are listed in all but the last row.

Hide checkbox, allows a branch to be hidden from branch selection in the main window. The point of that is to reduce clutter, if you have a lot of branches but don't want to delete them.

A branch may be deleted, obviously something you only do if you are done working on that branch. This could mean either that 1) you have merged your work to another branch, or 2) that your work led to a dead-end and you wish to discard it. Press the button, and confirm in the dialog poping up if you wish to delete this branch, or cancel.

In the last row, you can add a new branch, by typing its name, and pressing the button. The branch name cannot contain all characters, so the text field stops you from typing forbidden characters

Git & system tools (built-in if empty)

Pragma-git has a built-in diff and merge tool. If the fields for external tools are left blank (or says pragma-git), the built-in tool will be used.

There are numerous alternative Diff and Merge tools to chose from (search internet for : Diff and Merge tool). You can install one of these to your system, and use it easily if known to git. See a list from the command line:
git mergetool --tool-help.

Pragma-git can open the file browser or a terminal, in the path of the current repository. If you have your favorite file browser or terminal installed, you can add the path for it to be used instead of the system defaults (blank field).

The settings for external tools are :

- Diff tool , lets Pragma-git show you differences between different revisions. The diff-program must be installed separately. One good diff program is "Meld", but there are tens of different programs to download

- Merge tool , lets Pragma-git help you solve file conflicts where git cannot decide safely on its own (conflicts arising from Merges, or Pull from remote repository where work has been done in both places)

- File browser , the path to preferred file browser (or empty for system default).

- Terminal , the path to preferred terminal (or empty for system default).

- Addition to path , if the external tools do not open, their path may not be accessible to Pragma-git. This can be fixed, by adding the path to the tools in this field. If you have different diff and merge tools, two paths may be needed. The two paths should then be separated by ";" for Windows, or ":" for Mac and Linux.


Note: the external diff/merge tools are not opened through the git config files, but from Pragma-git settings. The cmd how to handle the diff/merge tools are however in the git config files, and should just work for one of the known tools.

Advanced: The name specified in above diff and merge tool settings have an underlying command defined in git config files. So, to use your own installed diff/merge software (which is not known to git) the cmd field has to be defined manually in one of the git config files. After that, you can enter the defined name in the diff/merge tool fields.

System Info tab

(click on tab)

This tab displays technical details useful for troubleshooting, support, and inspecting active configurations.

The information is organized into the following sections:

  • Project folder: Displays the path of the currently selected repository (local folder or SSH server path). For server repositories over SSH, this section also clearly displays:
    • Private key (local) — The absolute path to the local private SSH key used to authenticate.
    • Public key (server) — The remote URL path pointing to the server's ~/.ssh/authorized_keys where your public key is registered.
  • Current Remote & Git credentials: Shows the active remote origin and credentials retrieved from the operating system's credential manager (via git credential fill).

    credential.username in local .git/config:
    • In normal Git operation, credential.username should be (not set). This allows the OS Keychain or credential manager to negotiate authentication dynamically without locking the repository to a single hardcoded account.
    • If a repository was previously locked with a stale or incorrect username in its local .git/config (which can cause repeated 401/403 errors and password prompt loops), a button is displayed. Clicking it immediately removes the username override from .git/config.
  • Git remote info: Displays metadata harvested from the remote hosting service (such as GitHub, GitLab, Bitbucket, or Gitea), including API connection status, API endpoints, and web repository links.
  • Pragma-git info & system's path: Shows software versions (Node, NW.js, Git) and the system environment PATH as seen by Pragma-git.
  • gitconfig files: Shows the configuration hierarchy (system, global, and local .git/config files).

To the right are links for bug reporting, documentation, or submitting ideas for improvements.
