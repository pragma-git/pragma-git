SSH Connection Configuration

This window allows you to configure, test, and repair SSH connections and cryptographic authentication keys for remote Git repositories accessed over SSH.

When is this window opened?

You can access this configuration window from several places in Pragma-git:

  • Settings → Repository → Add Repo: Using the [Setup SSH...] button or after a failed login test when adding a remote repository.
  • Settings → Repository → Clone: Using the [Setup SSH...] button or after a failed login test when cloning to or from a remote server.
  • Repository table: Clicking the [Fix] button in the Project folder column when an SSH repository fails authentication (for instance, when marked with (key rejected)).

Target Server

The Target field specifies the remote SSH user and host (for example, username@server.example.com or git@192.168.1.50). When configuring a new repository in Add Repo or Clone, this is entered into the username and server fields. When opened via [Fix] for an existing repository, the target server is automatically detected from the repository URL.

SSH Keys & Security

Pragma-git uses standard public-key cryptography to communicate securely with your remote Git server without requiring you to repeatedly enter your password:

  • Default key: If no custom key is selected, Pragma-git defaults to your standard personal SSH key (typically ~/.ssh/id_ed25519 or ~/.ssh/id_rsa).
  • Select key...: Click to pick an existing private SSH key stored on your local computer.
  • Reset to default: Clicking the ✕ button removes the custom key selection and reverts back to the default key.

Important security note: Your private SSH key never leaves your local computer. Pragma-git never uploads, transmits, or exposes your private key. When deploying authentication credentials to a remote server, Pragma-git exclusively copies the matching public key (the .pub file) to the server's ~/.ssh/authorized_keys list.

Generating a New SSH Key

If you do not have an SSH key pair or want a dedicated key for this server:

  1. Click to open the key generation panel.
  2. Pragma-git suggests a recommended file path in your ~/.ssh/ folder (for example, ~/.ssh/id_ed25519, or a host-specific path if that key already exists).
  3. Click to generate a new modern, high-security ED25519 key pair.
The newly generated key is created without a passphrase so that automated Git operations (fetch, pull, push, and remote status checks) can run without interruption.

Testing and Deploying Keys

Test login
Click to test passwordless authentication to the target server using the active SSH key. Pragma-git performs a non-interactive test with a 4-second timeout to confirm whether the server accepts your key.
Deploy public key
If the test fails because your public key is not registered on the remote server (key rejected), the button appears. Clicking it prompts for your remote user password once and securely installs your public key into the remote server's ~/.ssh/authorized_keys file.
Generate new key
If no usable SSH key is found on your computer, the button appears as an immediate shortcut to generate one.

Saving Changes

  • saves the selected SSH key configuration. If you opened the window from a broken repository in the repository table, it re-verifies the connection and clears the failure warning upon success.
  • discards any unsaved key selections and closes the dialog.

Windows Platform Requirements

On Windows, Pragma-git executes SSH remote repository commands and SSH authentication utilities via WSL (Windows Subsystem for Linux) to provide full POSIX SSH socket compatibility and connection reuse.

If WSL is not yet installed on your Windows machine, open PowerShell as Administrator and run:
wsl --install

Once installed, reboot Windows if prompted, then launch Pragma-git.
